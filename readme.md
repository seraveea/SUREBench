# SUREBench

SUREBench is a benchmark for evaluating semantic uncertainty quantification (UQ) in black-box LLM generation. The workflow has three steps:

1. Sample multiple answers for the same question.
2. Compute uncertainty scores from the answer set.
3. Evaluate task performance and UQ quality (e.g., AUROC, AUPRC, PRR) under black-box constraints.

Supported tasks:
`triviaqa`, `nq`, `coqa`, `squad`, `bioasq`, `svamp`, `gsm8k`, `xsum`, `aeslc`, `cnn_dailymail`, `multi_news`, `wmt19`.

Most datasets are loaded through Hugging Face. BioASQ should be downloaded from the official website:
https://www.bioasq.org/participate/challenges

## Project Structure

- `generate_answer.py`: Multi-sample answer generation (outputs answer sets)
- `uq_compute.py`: UQ score computation from answer sets
- `evaluation.py`: Task and UQ evaluation
- `uq_methods/`: UQ method implementations (DSE, GWC, KLE, SNNE, LUQ, etc.)
- `eval_pipelines/`: Dataset-specific evaluation pipelines

## Quick Start

Example with `triviaqa + qwen3-8b`.

Set dataset root first:

```bash
export SUREBENCH_DATA_ROOT=/path/to/your/data
```

### 1) Generate Answer Set

To reproduce the results we shown in the paper, first the answer set needs to be generated by sampling multiple times from the model.

```bash
python generate_answer.py \
	--data_root /path/to/your/data \
	--dataset triviaqa \
	--model qwen3-8b \
	--repeat 10 \
	--temperature 1.0 \
	--result_file output/triviaqa/qwen3-8b/triviaqa_qwen3-8b.json
```

For SUQ deployment, you can formulate the output as a json file and call the unceritnaty method directly without running the answer generation script. The expected format of the answer set file is as follows:


```json
{
  "answers": [
    {
      "question_id": "unique_question_id_1",
      "question": "The question text for question 1",
      "answers": [
        "Sampled answer 1 for question 1",
        "Sampled answer 2 for question 1",
        "... more samples ..."
      ]
    },
    {
      "question_id": "unique_question_id_2",
      "question": "The question text for question 2",
      "answers": [
        "Sampled answer 1 for question 2",
        "Sampled answer 2 for question 2",
        "... more samples ..."
      ]
    },
    "... more questions ..."
  ]
}
```


### 2) Compute Uncertainty

```bash
python uq_compute.py \
	--answer_set_path output/triviaqa/qwen3-8b/triviaqa_qwen3-8b.json \
	--uq_method kle \
	--result_file uq_output/triviaqa/qwen3-8b/triviaqa_qwen3-8b_kle.json \
	--nli_cache_path uq_output/cache/triviaqa_qwen3-8b_nli.pkl
```

### 3) Run Evaluation (Task + UQ)

```bash
python evaluation.py \
	--data_root /path/to/your/data \
	--task both \
	--dataset triviaqa \
	--model_name qwen3-8b \
	--generation_path output/triviaqa/qwen3-8b/triviaqa_qwen3-8b.json \
	--uq_path uq_output/triviaqa/qwen3-8b/triviaqa_qwen3-8b_kle.json \
	--uq_type kle \
	--uq_string kl_regularized_uq
```

Evaluation outputs are saved to `eval_results/` by default.

## Common Arguments

- `generate_answer.py`
	- `--model_root`: Model root directory (`SUREBENCH_MODEL_ROOT` or `./models` if empty)
	- `--repeat`: Number of samples per question
	- `--temperature`: Sampling temperature
	- `--max_new_tokens`: Max tokens per generation
- `uq_compute.py`
	- `--model_root`: Model root directory (`SUREBENCH_MODEL_ROOT` or `./models` if empty)
	- `--uq_method`: UQ method name (e.g., `kle`, `discrete_gwc`, `discrete_snne`, `discrete_luq_pair`, `discrete_semantic_density`, `continuous_luq`)
	- `--nli_cache_path`: Path to NLI cache file (recommended)
- `evaluation.py`
	- `--task`: `qa` / `uq` / `both`
	- `--uq_string`: UQ field name used for evaluation

## Output File Convention

- Answer set: `output/<dataset>/<model>/<dataset>_<model>.json`
- UQ results: `uq_output/<dataset>/<model>/<dataset>_<model>_<uq>.json`
- Evaluation results: `eval_results/*.json`

## Notes

- Offline mode is enabled by default (`HF_HUB_OFFLINE=1`, etc.).
- Configure dataset and model roots to match your environment.
- `trivia` and `triviaqa` are both handled in evaluation, but using `triviaqa` consistently is recommended.

## Dataset Paths To Fill

Make sure required datasets are available locally or in Hugging Face cache.
Dataset paths are resolved in this order:

1. `--data_root` (highest priority)
2. `SUREBENCH_DATA_ROOT` environment variable
3. default `./data`

Expected layout under your data root:

```text
<DATA_ROOT>/
	triviaqa-rc/qa/wikipedia-dev.json
	coqa/coqa-dev-v1.0.json
	SQuAD/dev-v2.0.json
	SVAMP/test.json
	BioASQ_Task12BGE/
		12B1_golden.json
		12B2_golden.json
		12B3_golden.json
		12B4_golden.json
	NQ/                     # HF cache dir for Natural Questions
	gsm8k/                  # HF cache dir for GSM8K
	xsum/                   # HF cache dir for XSum
	aeslc/                  # HF cache dir for AESLC
	cnn_dailymail/          # HF cache dir for CNN/DailyMail
	multi_news/             # HF cache dir for MultiNews
	wmt19/                  # HF cache dir for WMT19
```

If your files are in different locations, pass explicit paths where supported (for example `--question_file`).

## Model Paths To Fill

If you need to generate the responses in this repo, please make sure required models are available locally.
Model paths are resolved in this order:

1. `--model_root` (highest priority)
2. `SUREBENCH_MODEL_ROOT` environment variable
3. default `./models`

```bash
export SUREBENCH_MODEL_ROOT=/path/to/your/models
```
